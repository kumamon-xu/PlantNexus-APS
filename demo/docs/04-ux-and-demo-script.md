# 交互设计与演示脚本

## 1. 体验目标

演示人员只需要理解订单、设备、交期和“是否接受新方案”，不需要理解 factory identity、event stream position、request fingerprint 或 attempt id。

首页把完整故事压缩为四个可见动作：

1. 初始化演示工厂；
2. 自动排产；
3. 设为仿真基线；
4. 插入加急订单。

底层 identity 和指纹仍被完整保存，但默认折叠在“技术证据”抽屉中。

### 2.2 初始化状态

空状态只显示场景说明和“初始化演示工厂”。初始化成功后展示精确计数、数据包指纹和生成器版本，并启用“自动排产”。

重置使用二次确认，说明它会切换到新的本地演示 run，当前 run 将进入有限保留归档。存在活动 job 时禁用重置并解释原因。

### 2.3 排产结果工作区

选项卡：

- 订单：订单号、零件族、数量、优先级、release、物料到齐、交期、计划完工、延期。
- 工厂甘特图：按车间分组，可继续展开到设备。
- 设备甘特图：单设备日历、维护、固定事实和计划任务。
- 计划负荷：按设备/车间的计划忙碌时长与可用日历时长。
- 校验与证据：Solver 状态、Validator、版本 lineage、hash 和阶段耗时。

所有表格支持搜索、优先级筛选、延期筛选和订单→甘特图联动。

### 2.4 加急订单抽屉

抽屉使用路线卡片，不暴露内部 routing/version：

- 简单隔套；
- 精密安装板；
- 复杂支架；
- 精密轴；
- 薄壁套；
- 阀体 / 壳体。

选择路线后显示：

- 工序链；
- 可能设备族；
- 数量；
- 工厂时区下的交期；
- 优先级；
- 预计新增工序数；
- “提交后将保留已完成、正在加工、硬锁及冻结窗口内任务”的说明。

提交确认摘要示例：

    新增加急单：复杂支架
    数量：6
    交期：2026-09-10 18:00（Asia/Shanghai）
    优先级：加急（Simulation 权重 12）
    新增工序：4

用户不输入 planning_scope_id、authority、stream position、request id、fingerprint 或 attempt id。

### 2.6 TASK-DEMO-05 已实现故事壳

D13 的实现基线位于 `demo/frontend`，默认业务界面和状态信息均为中文：

- 顶部固定显示“仿真环境 · 非生产”、当前 run 短标识和重置入口；
- 四步流程只由服务端 `story_state` 驱动，不在浏览器维护影子状态；
- 场景规模读取 ScenarioManifest，Showcase 默认展示 132 单、610 工序、24 台设备和 10 天周期，Smoke 仅用于快速回归；
- Job 面板展示服务端阶段、开始时间、真实耗时和求解上限，不构造百分比；
- Solver、Validator、交付 KPI 只读取统一 Schedule view，浏览器不重新计算；
- 发布仿真基线必须二次确认，并提交服务端 revision、content fingerprint 与可恢复幂等身份；
- 完整 ID、指纹和英文枚举只出现在默认收起的“技术证据”中，原始异常和 session token 不进入可见文案；
- D14 的订单/甘特/负荷已接入下方工作区；D15 进一步把第四步接成业务化加急表单和服务端权威版本比较。

当前响应式验收覆盖 1440×900 与 1024×768，两者均无页面级横向滚动。初始化、自动排产、打开发布确认和确认发布均验证了键盘路径；确认对话框自动聚焦主要确认按钮，并支持 Escape 取消。

### 2.7 TASK-DEMO-06 已实现初始排产工作区

D14 在 current `PUBLISHED` 仿真基线下自动出现，默认业务界面和信息继续使用中文：

- 四个页签为“订单与交期”“排程甘特”“计划负荷”“校验与证据”；
- 订单表按延期、优先级和交期排序，支持订单/产品、等级、交付状态筛选，并以只读 GET 聚焦该订单全部工序；
- 甘特默认使用 72 小时时间窗与 160 条服务端分页，可切换工厂/车间/设备、状态、前后窗口和全周期；不会把 580 个 assignment 同时挂载为可视节点；
- 完成事实、加工中、硬锁、软锁、冻结窗口、非工作时段和维护停机均使用文字/图形双编码，并提供可展开的等价明细表；
- 计划负荷按服务端 `busy_seconds / available_seconds` 降序显示，明确说明它不是设备综合效率（OEE），不推导实际开动率或良率；
- 求解状态、独立校验、交付指标、版本与证据链均从服务端展示契约读取；初始排程的稳定性显示“不适用”，不虚构比较基线；
- 工作区刷新、筛选、分页、时间窗和订单联动只产生 GET；浏览器导航时建立本地 HttpOnly 会话的 POST 不属于工作区业务写操作。

真实 Showcase 浏览器证据覆盖 132 单、580 assignments、24 台设备、1440×900 与 1024×768；两个宽度都无页面级横向滚动，窄屏只允许甘特容器内部横向滚动。

### 2.8 TASK-DEMO-07 已实现加急重排与版本比较

D15 在 current `PUBLISHED` 仿真基线下开放“插入加急订单”，默认业务界面和信息全部使用中文：

- 路线卡直接读取批准资产，只展示 `CNC-ROUTE-3`～`CNC-ROUTE-6` 四条路线及中文工序链；演示人员只填写数量、北京时间交期、优先级和备注；
- active run、current base、事件、request、attempt、fingerprint 和幂等身份不作为业务输入；current base 只读展示，服务端提交时再次执行 stale 校验；
- 二次确认明确说明新方案只保存为草稿，不自动发布，也不替换当前仿真基线；已接受命令的精确 payload 与幂等键持久化，刷新后只能恢复或重试同一命令；
- Job 面板展示十个真实阶段、经过时间和 30 秒求解上限，不显示伪造百分比；`FEASIBLE + Validator PASS` 只称“已找到并验证可行”；
- 成功后自动打开 PUBLISHED → DRAFT 比较，默认只看 `ADDED`、`CHANGED` 与 `REMOVED_BY_FACT`，可切换“保持不变”或“全部工序”，并支持订单/设备筛选及每页 120 道的服务端分页；
- 每道工序以原方案/新方案双时间条及等价文字同时显示设备、开始时间和偏移；交付、稳定性、ChangeReport 与 Validator 都直接读取服务端证据；软锁偏离明确表述为允许的稳定性代价，不混同硬约束失败；
- durable 成功后的 `comparison_reference` 由 bootstrap 恢复。浏览器刷新后 active job 为空、比较仍可自动装载，且不会产生第二个 urgent POST。

真实 Showcase D15 浏览器样本在 132 单/580 个既有 assignments 的 current `PUBLISHED` 上插入 5 道工序，约 21 秒完成（求解阶段约 14.24 秒），得到 `FEASIBLE + Validator PASS` 的 v2 `DRAFT`。ChangeReport 为 5 `ADDED`、25 `CHANGED`、555 `UNCHANGED`，设备变更 3 道；1440×900 与 1024×768 均无页面级横向滚动。该结果是一个 synthetic early sample，不是 p95、目标机基线或 SLA。

## 3. 甘特图视觉编码

初始排程：

- 普通任务：中性蓝；
- 重点订单：深蓝边框；
- 加急订单：橙色；
- COMPLETED：实心灰绿并带完成图标；
- RUNNING：带进度纹理；
- 硬锁：锁图标与实线边框；
- 软锁：虚线边框；
- 冻结窗口：浅蓝背景；
- 维护停机：斜纹红灰背景；
- 非工作时间：浅灰背景。

前后比较：

- 基线 assignment：灰色轮廓；
- 新 assignment：主色实心；
- UNCHANGED：低饱和绿色；
- CHANGED：紫色；
- ADDED：橙色；
- REMOVED_BY_FACT：灰色删除线。

不能只靠颜色表达状态；每类同时使用文本、图标或线型。鼠标悬停与键盘聚焦显示相同详情。

## 4. KPI 与口径

### 4.1 初始排程

- 按期订单率：计划完工不晚于交期的订单数 / 有交期订单数。
- 延期订单数与延期率。
- 优先级加权延期秒数。
- makespan。
- 计划设备负荷：选定区间内计划占用秒数 / 可用日历秒数。
- 瓶颈设备：计划负荷最高的设备，不称为实际瓶颈证据。

### 4.2 重排稳定性

直接显示 ChangeReport 的：

- soft_lock_violations；
- changed_existing_operations；
- resource_changes；
- absolute_start_shift_seconds；
- unchanged_existing；
- comparable_existing；
- unchanged_ratio。

另显示每道工序的 resource_changed、start_shift_seconds、end_shift_seconds 和 duration_delta_seconds。所有汇总由服务端从规范文档构建；前端只格式化单位。

若 unchanged_ratio 的状态是 NOT_APPLICABLE_NO_COMPARABLE_OPERATION，页面显示“不适用”，不能显示 0%。

### 4.3 交付对比

展示 before KPI 与 after KPI 的：

- 加权延期；
- 延期订单数/率；
- makespan；
- 加急订单计划完工与交期差；
- 原有订单中变好、变差和不变的数量。

最后一项属于 demo presentation 派生指标，服务端必须给出公式、operation/order universe 和来源指纹。

## 5. 求解与校验文案

[CP-SAT 官方状态说明](https://developers.google.com/optimization/cp/cp_solver)区分 OPTIMAL、FEASIBLE、INFEASIBLE 和 UNKNOWN。页面固定使用：

| 状态 | 中文主文案 | 次要说明 |
|---|---|---|
| OPTIMAL 且 Validator PASS | 已证明最优 | 在当前模型、数据和求解参数下已证明最优 |
| FEASIBLE 且 Validator PASS | 已找到并验证可行 | 尚未证明最优；可用于本次演示比较 |
| UNKNOWN 且无 candidate | 达到求解限制，未找到可接受排程 | 不能据此判断问题不可行 |
| INFEASIBLE | 已证明不可行 | 查看预检与约束诊断 |
| 任意状态且 Validator FAIL | 排程校验失败 | 已阻止创建或切换版本 |

不得使用“优化完成”掩盖 FEASIBLE，也不得把 UNKNOWN 翻译为“不可行”。

## 6. 进度反馈

Job 面板显示：

- 当前真实阶段；
- 当前阶段开始时间；
- 总经过时间；
- SOLVING 的上限；
- 已完成阶段及各自耗时；
- correlation id 的短形式；
- 可恢复失败时的重试动作。

示例：

    正在求解排程
    已用 12.4 秒 · 上限 30 秒
    前置数据校验 0.8 秒 · 问题构建 0.4 秒

不显示“67%”之类不可验证的进度，也不循环播放虚假的工序计数。

## 7. 标准演示脚本

### 7.1 演示前检查

1. 从仓库锁定 commit 启动 Demo。
2. 运行 health 和 asset hash 检查。
3. 点击重置，确认 scenario、seed 和计数与 golden manifest 一致。
4. 使用专项基准验证过的脚本化加急 payload；如果机器或依赖版本不匹配，先运行 smoke。

### 7.2 正式讲解

步骤一：初始化

讲解：这是一个单工厂、三个车间、24 台设备的精密机加工场景。固定 seed 生成 132 个订单、610 道工序，因此每次演示的数据来源和规模一致。

操作：点击“初始化演示工厂”，展示计数、日历、维护、物料与执行事实摘要。

步骤二：自动排产

讲解：数据先经过同一套标准导入和校验，再构建 Snapshot 与 PlanningProblem；求解结果还要经过独立 Validator。

操作：点击“自动排产”，观察真实阶段。完成后先读 Solver 状态，再读 Validator。

步骤三：查看初始方案

讲解：按订单看交期，按工厂/车间/设备看甘特图，再看计划负荷。强调计划负荷不是 OEE。

操作：筛选重点/加急订单，展开一台有维护窗口的设备，查看已完成、运行中和锁定任务。

步骤四：设为仿真基线

讲解：动态重排不会以未评审草稿为基线。现在显式批准并发布到 Simulation 内部目标。

操作：点击“设为仿真基线”，确认版本从 READY_FOR_REVIEW 进入 PUBLISHED。

步骤五：插入加急单

讲解：演示人员只填路线、数量、交期和优先级，底层事件 identity 由系统安全生成。

操作：选择专项基准中已冻结的路线与 payload，提交。指出系统先导入订单事实，再产生 URGENT_DEMAND_RECEIVED。

步骤六：动态重排

讲解：已完成、正在加工、硬锁和冻结窗口内任务被保留，其余任务按交付优先、稳定性和 makespan 的字典序目标重排。

操作：观察真实 job 阶段和有限求解状态。

步骤七：比较新旧版本

讲解：新结果是 DRAFT，不会替换当前基线。ChangeReport 是变更分类的权威，Validator 是可接受性的门。

操作：

- 先用“仅看变化”展示移动工序；
- 再切到“保持不变”证明稳定性；
- 查看设备变更与开始时间偏移；
- 查看加急单交期和原订单交付变化；
- 展开 ChangeReport 与 Validator 指纹。

## 8. 脚本化加急样本

当前 D15 开发与浏览器演示使用以下固定样本；它还不是 D17 的 immutable 性能基线：

| 字段 | 候选值 |
|---|---|
| route_template_id | CNC-ROUTE-5（精密套筒类，5 道工序） |
| quantity | 5 |
| due_at_local | 2026-09-09T18:00:00（Asia/Shanghai） |
| priority_class | URGENT（加急，权重 12） |
| note | Showcase 固定加急精密套筒 |

D15 单次真实浏览器链已证明新增/变化/保持不变、Validator PASS、ChangeReport 自检和 DRAFT/current Publication 边界。冻结为正式 D17 样本前仍须证明：

- 新增工序数等于模板深度；
- 至少一条既有工序发生变化；
- 至少一条可比既有工序保持不变；
- 已完成、正在加工、硬锁与冻结任务全部得到保留；
- 新排程 Validator PASS；
- ChangeReport 自检 PASS；
- 结果在目标演示机 5 次重复运行中稳定可复现。

如果候选样本不满足上述条件，调整 fixture 参数并重新基准；不能在现场反复试随机交期。

## 9. 失败演示与恢复

| 失败 | 页面行为 | 恢复 |
|---|---|---|
| 导入校验失败 | 显示数据错误码，不创建 Snapshot | 修复 fixture 或重置 |
| 求解 UNKNOWN 且无 candidate | 保留原基线，说明未找到可接受方案 | 用相同输入提高已批准的演示上限后重试 |
| INFEASIBLE | 保留原基线，显示已证明不可行及诊断 | 调整加急交期/数量后创建新命令 |
| Validator FAIL | 红色阻断，不生成/切换版本 | 查看技术证据，修复实现 |
| 发布在批准后失败 | 显示 APPROVED 可恢复状态 | 重试发布，不重新求解 |
| 浏览器刷新 | 从 /bootstrap 恢复 active job 和页面 | 自动继续轮询 |
| 服务重启 | RUNNING 标记 INTERRUPTED | 从安全边界显式重试 |
| stale base | 阻止提交，刷新当前 PUBLISHED | 重新确认加急表单 |

不能使用预录结果冒充本次 live solve 成功。

## 10. 可访问性与演示环境

- 主要操作支持键盘，焦点顺序与步骤一致。
- 所有图例都有文字，颜色对比达到 WCAG AA 的常规文本要求。
- 甘特图提供等价表格视图。
- 时间、秒数和百分比有统一本地化格式。
- 投影仪宽屏 1440×900 下无需浏览器缩放即可完成主流程。
- 1024 像素宽度仍能完成操作；移动端只保证查看，不作为演示主设备。
- 长 ID 默认截断，但复制时得到完整值。
- 所有提示明确标识 Simulation。
