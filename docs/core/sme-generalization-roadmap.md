# SME 通用产品演进路线

本路线以公开 v0.1.0 为起点，面向中小企业的通用离散制造 APS。六个阶段是投资与验收单元，不对应六个固定版本号或工期承诺。当前只建立规划；实现状态仍由[能力矩阵](capability-matrix.md)、[API 清单](../contracts/api-development-checklist.md)和版本化机器合同说明。

研发当前没有可用的真实工厂环境或历史数据。P9～P14 使用可重复的模拟/仿真数据推进合同、约束、参数和性能验证，不要求真实项目接入作为开发或工程发行的前置门。后期真实数据校准以独立接入/回放流程恢复，不能把仿真结果解释为现实精度、产能或生产上线许可。决策依据见 [ADR-0020](../adr/ADR-0020-simulation-first-sme-generalization-roadmap.md)。

## 为什么这样排序

现有核心已具备 FJSP/DAG、候选设备差异工时、基本日历、运行事实、锁定、版本/审批/发布、动态重排服务，以及 Runtime/SDK/Kit 的工程底座。仍需区分内部实现与正式分发中的可用功能：v0.1.0 的 Runtime Workspace adapter 只绑定读版本、审批、发布、创建/读取导出五类操作，动态重排 router 也不等于 Runtime 已装配其 application。

因此先补正式链路与准入一致性，再固定数量/时间/执行基础语义；辅资源与换型先于材料分配，材料分配再支撑 CTP、滚动决策和拆并批。通用制造语义由 Core 承载，行业画像/经批准配置提供默认选择，企业差异使用受控扩展。不能要求每家中小企业编写插件才能使用基本制造语义。

## 六阶段成果

| 阶段 | 交付成果 | 完成时应看到的结果 |
|---|---|---|
| P9 现有能力产品化与 Runtime 闭环 | 冻结实际能力、34 项 OpenAPI operation 与 Runtime 装配覆盖矩阵，区分路由、内部服务、正式装配、验证证据。 | 宿主从正式 Runtime 完成首次排程、查看与比较、人工调整、执行事件、异步重排、审批发布和成果导出；所有候选经过统一且独立的准入校验。 |
| P10 制造语义与数据合同底座 | 区分需求、生产单、显式批次和工序实例，定义数量守恒及来源追溯；不提前自动拆单。 | 同一套标准数据可以正确表达订单、批次、数量、实例工时、日历、执行进度和排程范围，形成后续高级能力可靠的共同基础。 |
| P11 联合资源与顺序换型 | 主资源与辅资源联合选择、容量、日历、占用数量、兼容性和替代集合。 | 设备、人员/工装等辅资源可联合排程，换型取决于真实前后工序顺序；首个受控扩展能够实际影响搜索。 |
| P12 物料数量分配与装配齐套 | 版本化库存/到货供给、工序需求、分配与预留、消费/释放的时序数量账。 | 多个订单竞争有限物料时不会重复占用，装配与中间产出按数量和可用时间获得可解释的齐套结论。 |
| P13 计划控制与决策支持 | CTP/插单 what-if，隔离场景、约束交期承诺依据及可行/未知/拒绝解释。 | 计划员能比较插单/承诺交期方案，在明确冻结和稳定性规则下滚动重排，并显式采纳可执行候选。 |
| P14 拆并批、联合批处理与外协 | 拆批与合并的数量守恒、批次追溯、最小/最大批量、转运批和实际进度继承；每项能力分步交付。 | 按明确策略处理拆批/合批、兼容联合批和固定供应商外协，交付后续真实项目离线回放与校准接入方法。 |

主线为 P9 → P10 → P11 → P12 → P13 → P14。固定供应商外协可在 P12 后经计划修订提前；完整批次联合加工可独立于自动拆批先交付。阶段编号不阻止合理解耦，但不得绕过直接依赖、版本合同与验收。

## 各阶段边界

### P9：现有能力产品化与 Runtime 闭环

- 冻结实际能力、34 项 OpenAPI operation 与 Runtime 装配覆盖矩阵，区分路由、内部服务、正式装配、验证证据。
- 规范现有 canonical JSON 的跨语言表示、哈希和兼容行为；保留旧版本字节与指纹。
- 补齐人工调整/锁定/校验/驳回、工作区读模型、事件投影与异步重排的正式 Runtime 链路。
- 首次求解、人工修改和重排统一执行 Core Validator 与已配置 Extension Validation Rule，拒绝未经验证的候选。
- 宿主与可选 Frontend 消费相同 API；验证新 Runtime 与 SDK/Extension/Kit 的精确兼容组合。
- 建立分层 synthetic 场景、保留集和运行基线，以可安装制品完成阶段 Gate 与独立 Exit。

边界：不增加辅资源、顺序换型、数量物料、拆并批等新排程约束；不把 Extension 回调/后验过滤表述为参与搜索；不改变生产上线门。

### P10：制造语义与数据合同底座

- 区分需求、生产单、显式批次和工序实例，定义数量守恒及来源追溯；不提前自动拆单。
- 版本化精确数量/计量单位与缩放规则，拒绝隐式舍入/溢出；按批量与候选设备计算实例工时及优先级。
- 日历覆盖范围、时区/边界、跨班工作量与允许续作语义；日历间断续作与任意抢占分别建模。
- 部分完工、剩余量、暂停、取消、纠错与报废/返工的明确支持边界；不得覆盖不可变历史事实。
- 规划范围、超期/超窗任务与受控未排原因：明确必排集合、延期代价和完整性，不以漏排改善 KPI。
- 发布机器字段字典、跨实体/跨字段规则、正反 JSON 示例、迁移/兼容和同路径回放合同；为后续历史来源/校准留显式版本与 provenance 接缝。

边界：不实施任意抢占、库存竞争、全自动拆批、ERP/MES Connector；本阶段不因预留来源字段放开真实输入或 Production。

### P11：联合资源与顺序换型

- 主资源与辅资源联合选择、容量、日历、占用数量、兼容性和替代集合。
- 准备/加工/清理等阶段占用，以及从本工序到指定下游释放事件的跨工序占用；资源持有不等同缓冲区容量。
- 初始 setup 状态、序列相关换型矩阵、非对称切换、换型占用资源与日历；手工调整后重新校验。
- 把制造资源技能标签与引擎 capability namespace 分开，按显式事实解析所需能力并给出解释；不猜缺失配置。
- 定义 Solver-neutral 的受控扩展贡献合同，经 Backend 编译进入搜索；影响可行性必须有独立 Validation Rule，objective 遵循批准层级。

边界：不开放任意 Python/CpModel 插件、不支持请求级代码上传；不实现 Buffer Capacity、多工厂或替代料。

### P12：物料数量分配与装配齐套

- 版本化库存/到货供给、工序需求、分配与预留、消费/释放的时序数量账。
- BOM/多输入装配齐套、供需关联及中间产出可用时点；有质量放行时按显式事实处理。
- 运行中、已完成、取消/重排的剩余需求与预留继承/释放，避免在新计划重复消耗。
- 发布分配明细、短缺与延期解释、物料约束 Validator 及 KPI/read/export。
- 与 P11 联合资源/换型组合，保留简单 material_ready_at 模式的明确兼容边界。

边界：不建设完整 WMS/财务库存账、不自动 MRP/采购、不优化替代料；库存来源仍由宿主负责。

### P13：计划控制与决策支持

- CTP/插单 what-if，隔离场景、约束交期承诺依据及可行/未知/拒绝解释。
- 滚动窗口及范围继承、细粒度锁定/冻结、可解释稳定性；与 P10 受控未排合同衔接。
- 人工调整的冲突定位和有界修复；改变已批准目标层级前必须单独 ADR。
- 多方案比较、显式采纳、候选来源与输入新鲜度检查，拒绝已过期候选。
- 诊断事实、假设组、约束冲突与处置建议；不把非最小冲突子集称最小集。

边界：不自动审批/发布、不默认改目标权重，不因规划滚动窗口自动引入 Decomposed/Hybrid Strategy。

### P14：拆并批、联合批处理与外协

- 拆批与合并的数量守恒、批次追溯、最小/最大批量、转运批和实际进度继承；每项能力分步交付。
- 兼容联合批处理、容量上下限、同批起止/工时、配方/质量兼容和等待代价；整批联合加工不依赖自动拆批。
- 固定供应商外协：显式运送/返回、供应商日历/容量/交期、在途与回厂事实；不做供应商网络优化。
- 后期校准接入包：宿主映射后的获授权离线数据 → 版本化 canonical 校验 → 隔离回放 → 分布/规则/工时偏差 → 人工批准参数候选；带接口/文件规范、样例、回滚与报告工具。
- 校准工具只用合成示例验证接缝；实际 Historical Replay/Planner comparison/Capacity Decision 留给有真实输入后的新计划。

边界：不要求当前取得真实工厂数据，不宣称完成现实校准；不恢复旧 P5/P7 执行卡，不做自动采购/多供应商网络优化或任意拆合。


## JSON、字典与合同随能力交付

每个能力必须同时落地人类语义、JSON Schema、字段字典、数据校验、Snapshot/Problem、Solver、独立 Validator、API/read model/export、正反例与运行证据。仅添加字段、注册枚举或 UI 按钮不代表支持。

P9 先明确现有字段、必填条件、未知字段/重复键/非有限数处理、规范序列化和跨语言哈希一致性；P10 建立字段级机器字典与精确数量、工时、日历、执行事实的共用底座；P11～P14 对每个新增能力增量扩展。禁止一次提前发布全部高级字段，随后静默忽略。

机器字典目标至少包括：英文路径/中文名称、对象主外键、类型与单位、精度/范围、必填条件、空值/缺省区别、来源 authority、跨字段/跨实体规则、例子、引入/废弃版本、消费者及能力依赖。P9 先形成现有语义目录，P10 再发布机器合同；本轮不改变现有字段。

兼容变更使用新 carrier/Schema version 与明确迁移；旧字节、旧 hash、旧 Kit 保持可重放。规划内的 B/G/S/D 编号、后续状态名称和示例不自动成为公开 enum 或 API。

## 与审核建议的取舍

| 建议方向 | 本项目安排 |
|---|---|
| 基础能力补强 | P9 正式链路；P10 数量/工时/日历/执行/范围；P13 控制深化 |
| 辅资源、换型、物料、装配 | P11/P12 分纵向切片交付，并提供组合场景 |
| 自动能力解析 | P9 先清点真实支持；P11 分离资源技能和引擎能力，并按事实解释解析 |
| Extension 参与排程 | P9 统一已有验证入口；P11 形成 solver-neutral 搜索贡献，不以回调执行替代 |
| 拆并批、联合批处理、外协 | P14；外协与整批处理按上述依赖可拆开 |
| 标准 JSON 与数据字典 | 贯穿各阶段，P10 建共用底座；不先建全量空壳 |
| 真实工厂校准 | 当前延后；P10 留来源/版本接缝，P14 留离线回放工具与接入说明 |
| 任意抢占、Buffer、多工厂、替代料、分解求解 | 本路线不承诺；独立必要性证据和新决定之后再规划 |
| AI 工时 | 保持现有 default-off、标准工时回退；合成数据不提供真实预测精度证明 |

旧 P5 退役计划不恢复。P9～P14 是新目标与新依赖，不能继承旧卡的执行授权、Test 结论或实现状态。原 P7 现实校准继续 deferred，后续需新任务承接。

## 统一退出标准

每阶段使用[仿真验证与校准策略](../simulation/generalized-product-validation-and-calibration.md)：人工可核验小例、独立负例/mutation、确定性多 seed、组合和连续扰动、保留集、复杂度/性能阶梯。预算在运行前冻结并记录环境，不能用事后阈值或“生成了很多数据”替代覆盖。

正确性是硬门：已接受候选的硬约束违反为零；其他情况如超时、无解、模型错误、未支持和允许未排必须准确区分。性能只声明相应场景与硬件下的结果。每阶段均有独立 Exit、公开能力状态同步和旧版本兼容证据；工程就绪与未来真实项目上线分别判定。
