# 通用产品仿真验证与后期校准策略

本文定义 P9～P14 的目标验证方法，不宣称新生成器、基准规模或校准接口已实现。当前没有真实工厂数据，阶段研发以模拟/仿真推进，真实校准不作为当前开发前置条件。

P9 的 B01～B10 覆盖单元、XS/S/M 复用范围、开发/保留 seed 预留、预算测量和逐项验收责任已在 [Runtime 基线](../contracts/runtime-capability-baseline.md#p9-仿真覆盖与验收冻结)冻结为设计输入。尚未生成场景或运行性能；新链预算为 PENDING_MEASUREMENT，P9-09 必须在性能验收前冻结 catalog/SIM 假设、精确环境和门限，缺项阻断后续 Gate。

## 校准的对象与结论

| 当前可做 | 当前不能从合成结果推导 |
|---|---|
| 输入/约束语义一致性、数量与时间不变量 | 某工厂真实工时、库存、班次与业务规则已经正确 |
| 算法参数、求解预算、场景生成分布与工程性能对比 | 真实分布、生产容量、固定 SLA 或任意规模可用 |
| 连续执行扰动、故障恢复、变更稳定性 | 已完成真实 Planner 验收、现场 UAT 或生产上线 |
| 预留接入/回放接口并用 synthetic 样例验证 | 真实历史已取得合法 authority 或已完成 Reality Gap |

“通用性”应报告覆盖了哪些制造语义与组合、未覆盖什么。增加随机样本数量不能弥补缺失的规则、错误 oracle 或未定义的事实。

## 分层场景与数据隔离

| 层 | 数据和验证方法 | 最小证据 |
|---|---|---|
| 可核验小例 | 人工推导或独立枚举，包含多个等质量解 | 可行性、数量/时间、目标值及独立计算说明 |
| 非法与边界例 | 基于合法事实单独构造错误输入/候选，不复用 Solver 判定代码 | 每个硬约束有能够触发的拒绝例，错误类型和无副作用边界 |
| 生成场景 | 多画像、多 seed、多因子分层抽样，含有意不可行与未知预算结果 | seed/版本/hash、覆盖矩阵、结果分布 |
| 连续扰动 | 事件→新快照→异步重排→候选→显式控制，多次延续 | 完成/运行事实、锁、预留/批次谱系保留与变化报告 |
| 复杂度阶梯 | XS/S/M 现有基线加有界候选 L/压力层 | 模型规模、建模/首解/求解/校验耗时、内存、质量与失败 |
| 独立保留集 | 在调参前固定的 seed/画像/结构组合，权限和使用记录可审查 | 与开发集独立的泛化结果；失败后归档原结果，新版保留集另立版本 |
| 制品链路 | 安装实际 Runtime/Kit，宿主 HTTP 经过 DB/queue/Worker | 应用内部 PASS 与发行组合 PASS 分开记录 |

已知可行样例可先构造人工可验证计划再派生输入，但必须加入独立来源的边界、扰动和不可行例，防止生成器与 Solver 共享同一个错误。Reference Scheduler 只做基线；它不证明 CP-SAT 最优，也不替代 Validator。

## 覆盖维度

持续覆盖工厂/资源规模、DAG 深度与汇合、候选密度、交期压力、日历碎片、工时/数量范围、运行比例、锁比例、跨车间比例和连续异常。随里程碑增加辅资源稀缺度/占用阶段、setup 矩阵、物料供需竞争、装配分支、窗口/候选陈旧、拆并批谱系、联合批兼容与外协时间。

采用单因素边界、成对组合和业务上高风险的三项以上组合，不要求盲目穷举笛卡尔积。每个支持声明都必须映射到正例、负例、组合和制品链路；未覆盖项记录 gap。所有分布/概率/画像参数均是版本化 Simulation assumption，不能默认成为生产配置。

## 指标、预算与门

正确性优先：进入可评审候选必须独立验证且硬约束违反为零；事实/锁/数量/物料/资源占用等适用不变量全部通过。Solver UNKNOWN 不能算 INFEASIBLE；允许未排的任务必须依 P10 合同单列，不能从 KPI 分母隐藏。

报告可行结果率及分母、各求解状态计数、交期/稳定性/换型/材料等待等适用业务指标、objective/bound/gap、模型规模、建模/首解/求解/校验耗时分布、峰值内存及失败重试。不用单次最佳耗时代表稳定表现。

每阶段第一个合同/基线任务须在实现验收前冻结：画像与规模、seed 分层及保留集、硬件/OS/Runtime/solver 版本、并行度、wall-time/内存预算、重复次数与目的、正确性门和可接受退化门。门限来自已测基线与目标预算，未测前标为待冻结，不在计划文档编造“5 分钟”“万人级”等承诺。

新能力先验证独立正确性，再做组合、再评性能/质量。基线不适用于某种新约束时显式说明，不能让忽略约束的贪心结果当可行对手。固定旧场景在兼容版本上回放；更新场景/生成器/参数时另存版本并说明变化。

## 正式链路和复现包

所有生成输入均走宿主 canonical HTTP/正式事件入口、Data Validation、不可变 Snapshot/Problem、同一 Runtime/Registry、异步 Worker 和独立 Validator。阶段验收不得依靠直接构造 CpModel、测试专用简化 Solver 或未打包服务注入。

每份证据绑定输入/hash、Scenario/Profile/Generator/Simulator 版本、seed、schema/rule、代码提交、Runtime/SDK/Extension/Kit 身份、solver 参数、环境、结果与候选校验。保留失败/UNKNOWN 与缩减重现样例；多个正确等价解不要求逐字相同排程序列，要求输入构建确定性和语义证据一致。

## 后期真实数据接入方法

1. 宿主按独立批准的映射与脱敏规则生成离线输入，保存来源、版本、截点、计量单位和 authority；APS 不开发 ERP/MES/WMS 专用直连。
2. 新任务批准真实 carrier/使用范围、来源授权、隐私/保留、环境隔离与兼容。现有 Simulation-only Schema 不能直接塞真实数据或改标识；通过显式版本演进进入同一校验链。
3. 在隔离历史回放环境中保留原始事实与历史计划，按 as-of 截点构建输入，不泄漏未来事实。禁止将历史结果直接写回正式计划。
4. 对比路由深度、候选密度、日历、瓶颈、工时/执行偏差、材料等待与规模分布，形成 Reality Gap；分别定位数据映射、规则和算法问题。
5. 人工批准新的工厂画像/配置/参数候选；回放历史保留集和既有 synthetic 回归，保留旧版本与回滚方法。不上线自动调权/改硬约束。
6. 需要真实部署时再执行目标环境容量、Planner review、UAT 和适用生产门。

预留的最小接缝是“外部映射文件 → versioned canonical consumer → replay runner → 差异报告 → versioned calibration proposal”，不是现在发布未实现的 HTTP endpoint。P9 记录责任边界，P10 设计数据/来源接缝，P14 提供离线接入包和合成演练。实际数据到达后的校准工作独立立项。
